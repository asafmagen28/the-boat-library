Implementation Guide: Pagination, Search & Sorting

Overview: The Big Picture

Previously, our application loaded all items from the database and filtered them in the browser. While this works for small datasets, it doesn't scale. We have now moved to Server-Side Filtering.

1
URL-Driven State: The search query, page number, and sort order are now stored in the URL (e.g., ?page=2&search=ocean).
2
API Synchronization: React Query automatically fetches new data whenever these URL parameters change.
3
Database Efficiency: The backend uses SQL LIMIT, OFFSET, and WHERE clauses to fetch only what's needed.

Frontend: URL-Driven State

In AuthorsPage.jsx, BooksPage.jsx, and ManageCustomersPage.jsx, we now use useSearchParams from react-router-dom.

1. Syncing State with URL

// Inside AuthorsPage.jsx
const [searchParams, setSearchParams] = useSearchParams();

const page = Number(searchParams.get('page')) || 1;
const search = searchParams.get('search') || '';
const sortBy = searchParams.get('sortBy') || 'surname';
const sortOrder = searchParams.get('sortOrder') || 'ASC';

// Fetching data using these params
const { data, isLoading } = useAuthors({ page, search, sortBy, sortOrder });

Why? This allows users to bookmark searches, share links to specific pages, and use the browser's "Back" button to navigate through their search history.

2. Handling Transitions

We use placeholderData: keepPreviousData in our API hooks. This prevents the screen from flickering to a loading state while fetching the next page.

// Inside authors.api.js
export const useAuthors = (params) => {
  return useQuery({
    queryKey: [...QUERY_KEYS.authors, params],
    queryFn: () => api.get('/authors', { params }).then(res => res.data),
    placeholderData: keepPreviousData, // Essential for smooth UX!
  });
};

Backend: Dynamic SQL Queries

The server now does the heavy lifting using Sequelize.

1. Service-Level Filtering

In authors.service.js, we construct a whereClause based on the search term.

const whereClause = {};
if (search) {
  whereClause[Op.or] = [
    { firstName: { [Op.iLike]: `%${search}%` } },
    { surname: { [Op.iLike]: `%${search}%` } },
  ];
}

const { rows, count } = await Author.findAndCountAll({
  where: whereClause,
  order: [[sortBy, sortOrder]],
  limit,
  offset: (page - 1) * limit,
});

Op.iLike is used for case-insensitive searching in PostgreSQL.

2. Sorting by Virtual Fields

For fields like availableCopies in books.service.js, we use sequelize.literal because it's a computed value.

Bonus: Optimistic Updates with Pagination

This was the trickiest part! Since our data structure changed from [Array] to { authors: [Array], totalAuthors: 100 }, we had to update our optimistic logic.

When adding a new author, we now update all active author queries to show the new author at the top immediately:

// Inside useAddAuthor
queryClient.setQueriesData({ queryKey: QUERY_KEYS.authors }, old => {
  if (!old || !old.authors) return old;
  return {
    ...old,
    authors: [optimisticAuthor, ...old.authors]
  };
});
